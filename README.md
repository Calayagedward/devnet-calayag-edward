## How to work in this repo

1. **Get your own copy** — click "Use this template" on the template repo (don't fork), which creates this exact structure under *your own* GitHub account.
2. **Work in branches** — create a new branch for each lesson/activity instead of committing straight to `main`. Push it, then open a Pull Request when you're done.
3. **Commit as you go** — small, meaningful commits (not one giant commit at the end) show your actual progress and thinking.

## Filling out a lesson file

Each lesson file starts as a template with sections for you to fill in **in your own words**:

- **What is this topic?** — explain it like you're teaching a friend who's never coded before. No copy-pasted definitions.
- **Key vocabulary** — the important terms, defined by you.
- **My own example(s)** — write your own working code example. Not the one from class.
- **A mistake I made** — something that confused you or tripped you up. This is genuinely useful — it helps you (and classmates who read it later) avoid the same mistake.

If you can explain a concept well enough that someone else could understand it from your file, you actually understand it. That's the whole point of this format.

## TIL.md

This is different from the lesson files. `TIL.md` is a running, dated log of small things you learn along the way — not a full topic, just quick one-liners whenever something clicks or trips you up:

```markdown
## Sept 25
- Learned that a function with no `return` still gives back `None`, not nothing.
```

Add to it whenever, not just during formal lessons. Many real developers keep a TIL log like this throughout their careers — it's a good habit to start now and to know me as your instructor means that I appreciate works that my students did and figured out themselves, with their hardwork, patience and perseverance. Nothing worthy comes easy class!

## Submitting your work

When you finish a lesson or activity, make sure it's committed and pushed, then paste your repo link into the matching assignment in Teams. That's it — no separate file uploads needed.
